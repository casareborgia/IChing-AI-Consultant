# SaMD 해당 여부 자가 대조

| | |
|---|---|
| 대상 | 주역 심층 AI 상담 서비스 |
| 기준 | 식약처 「의료기기와 개인용 건강관리(웰니스) 제품 판단기준」 |
| 판단일 | 2026-08-27 |
| 판단자 | 개발자 자가 대조 (식약처 민원 질의 회신 아님) |
| 결론 | **웰니스 제품으로 판단.** 아래 네 가지 조건을 유지하는 것을 전제로 한다 |

이 문서는 공식 유권해석이 아니다. 지침으로 자가 대조하고 근거를 남긴 것이며,
확실히 하려면 식약처에 의료기기 해당 여부를 질의해 회신을 받아야 한다.

---

## 1. 판단 구조

지침은 **사용목적**과 **위해도** 두 축으로 가른다. 사용목적이 비의료용이어도
위해도가 높으면 의료기기로 본다. 그래서 두 축을 따로 본다.

### 사용목적

괘를 뽑아 해석하고 대화로 성찰을 돕는다. 지침이 웰니스 예시로 드는
'스트레스 관리'에 해당한다. 진단·치료·경감·처치·예방을 목적으로 하지 않는다.

### 위해도 — 쟁점은 여기다

문제가 되는 것은 **[0] 안전 스크리너**다. 사용자 발화를 분석해 5단계
(`NORMAL` / `CAUTION` / `ASK` / `BLOCK_SCOPE` / `BLOCK_CRISIS`)로 분류하고,
위기로 판정되면 괘 도출을 중단한다.

이 동작이 **자살 위험도 평가**로 읽히면 정신과적 스크리닝에 가까워진다.
그리고 오탐·미탐이 생명과 직결되므로 "위해도가 낮다"고 단정하기도 어렵다.

그래서 위해도를 낮게 유지하는 쪽으로 설계를 고정한다 — 스크리너를
**평가 도구가 아니라 차단 장치**로 두는 것이다. 등급을 산출하되 사용자에게
알리지 않고, 판정 결과로 하는 일은 "우리 서비스를 멈추고 공공 기관으로
넘긴다" 하나뿐이다.

## 2. 웰니스에 남기 위해 지키는 것

네 항목 모두 현재 구현에서 지켜지고 있음을 확인했다. **깨뜨리지 말 것.**

### ① 진단하지 않는다

병명·약물·의학적 판단을 언급하지 않는다. 설계 원칙 4이며 프롬프트 네 개
(`counsel.md` · `interpret.md` · `safety_screening.md` · `journal.md`)에 명시돼 있다.
`safety_screening.md`는 "진단하지 마십시오. '우울증으로 보입니다' 같은 말은
분류가 아닙니다"라고 못 박는다.

### ② 판정 등급을 사용자에게 보여주지 않는다

`BLOCK_CRISIS`는 내부 라벨이고, 화면에는 "지금 하신 말씀을 그냥 지나칠 수
없었습니다"라는 문구와 공공 핫라인만 나간다.
`tests/test_agents_safety.py::test_사용자_출력에_내부_라벨_미노출_전수_검증`이
이를 강제한다.

> **다만 한 가지 정정이 필요하다.** API 응답 본문에는 `safety_category`가
> 그대로 실려 나간다(`api/main.py:141`, `:202`). 프론트엔드는 이 값을
> 위기 지원 카드를 띄울지 정하는 불리언으로만 쓰고 화면에 렌더하지 않지만,
> 브라우저 개발자도구의 네트워크 탭에서는 원시 라벨이 보인다.
>
> **화면상으로는 지켜지고 응답 페이로드에서는 새고 있다.** 등급 표시를
> 하지 않는다는 원칙을 엄밀히 지키려면 응답에서 `safety_category`를 빼고
> `is_crisis` 불리언만 남기면 된다. 프론트엔드는 이미 그것만으로 동작한다.

### ③ 치료를 제공하지 않는다

위기 판정 시 자체 개입(상담·위로·조언)을 하지 않는다. 공공 핫라인으로
이관하고 서비스를 멈춘다.

- 안내처: 109(자살예방) · 1577-0199(정신건강 위기) · 1388(청소년) · 1366(여성긴급)
- 세션 상태를 `safety_redirect`로 바꿔 괘 도출을 중단한다
- `CRISIS_LATCH_HOURS`(기본 24시간) 동안 같은 사용자에게 괘를 뽑지 않는다

### ④ 효과를 주장하지 않는다

앱 푸터에 "본 서비스는 의학적·심리적 진단을 제공하지 않으며 자율적 성찰을
지원합니다", 위기 지원 카드에 "본 서비스는 의학적·심리적 치료를 대체하지
않습니다"를 표시한다. 증상 개선·치료 효과를 표방하는 문구를 쓰지 않는다.

## 3. 넘어갈 수 있는 선 — 하지 말 것

기능을 늘릴 때 유혹이 생기는 자리다. 아래는 사용목적이나 위해도를 바꿔
의료기기 쪽으로 넘어가게 만들 수 있다.

| 하면 안 되는 것 | 왜 |
|---|---|
| "고위험군입니다" 같은 등급 표시 | 위험도 평가 결과의 사용자 고지 = 스크리닝 도구 |
| PHQ-9 등 임상 척도를 점수로 노출 | 검증된 임상 도구의 사용 = 의료적 평가 |
| 위험도 추이 추적·모니터링 | 상태 경과 관찰 = 진단 보조 |
| "우울감 개선" 류의 효과 문구 | 사용목적이 치료·경감으로 바뀐다 |

새 기능이 이 넷 중 하나에 닿으면 **기능을 넣기 전에 이 문서를 다시 열 것.**

## 4. 남은 일

- [ ] 식약처 민원 질의로 공식 회신 확보 (최종 확인 수단. 현재는 자가 대조까지)
- [ ] `safety_category`를 API 응답에서 제거할지 결정 (§2-② 정정 항목)
- [ ] 위기 래치 해제 시점 정책 확정 — 지금은 24시간 시간 창이고, 이는 타협이다.
      `safety_screening.md` 판정 규칙 8은 "해제는 사람이 판단합니다"라고 하는데
      이 앱에는 판단할 사람이 없다
- [ ] 인증 도입 — `user_id`가 클라이언트에서 검증 없이 오므로 위기 래치를
      우회할 수 있다. "위험 판정 시 서비스를 멈춘다"는 이 문서의 근거가
      클라이언트 값 하나로 풀리는 상태다

마지막 항목이 이 자가 대조에서 가장 약한 고리다. §2-③은 서비스 정지를
근거로 위해도가 낮다고 주장하는데, 그 정지가 실제로 강제되지 않는다.
배포 전에 막아야 한다.
